# TieZ Fluent 暂存区与 Markdown 便笺开发计划

日期：2026-10-16。状态：开放讨论稿，尚未实施功能。

依据：当前工作区源码静态检查、CopyQ 官方文档、Tauri / Microsoft 官方文档。工作区已有未提交修改，本计划以当前文件为准，不把功能归属武断区分为上游或分支新增。本次没有启动应用或做性能基准；所有内存区间均为工程估算或候选预算。

## 1. 产品定位

剪贴板历史记录“刚才复制过什么”；暂存区保留“这件事接下来要用什么”；便笺记录“我的想法与处理结果”。三者能互相添加，但保留独立的保存、清理和同步规则。

暂存区是显式收集的持久材料集：用户主动拖入、粘贴或通过命令添加，重启后保留。AI 只是对用户选中材料执行的一项可选操作。无需 AI 也应完整解决跨窗口、跨时间搬运材料的问题。

演讲资料页确认 Scott Jenson 于 2026-09-19 发表了相应演讲，摘要涉及输入、数据流与桌面范式。本文关于 Shelf / Working Memory 的产品阐释以用户提供的演讲理解为设计输入；没有将视频摘要当作完整逐字稿。

### 必须在设计中处理的现状

1. `delete_with_conn()` 会清理历史附件。暂存区若只引用历史 ID 或原附件路径，会随清理失效。
2. 历史查询先读取、解密完整内容，再由 command 截断给 UI；这减少 IPC 数据量，却没有消除后端全量读取的峰值。新列表应直接查摘要元数据。
3. 虚拟列表只约束挂载节点；`useHistoryFetch.ts` 会逐页累计历史数组，暂存区还需要有上限的数据页缓存。
4. 图片管线部分路径会经历完整读入、解码、PNG 编码和 Base64 转换。批量拖入不要直接复用这一整条路径。
5. `richTextSnapshot.ts` 的缓存按 240 条限制，尚非按字节预算；多个 WebView 也各有 JS 状态。不能简单复制到每个新面板。
6. 紧凑预览当前设置为不接收鼠标交互与不获取焦点。可借鉴其窗口模式，但不能直接当成可编辑桌面便笺。
7. 原生拖放控制器当前使用 `mem::forget` 保持存活；若扩展为动态窗口，要建立随窗口关闭注销、释放的明确生命周期。

## 3. 从 CopyQ 借鉴什么

| 借鉴对象 | 在 TieZ 中的实现 | 优先级 |
| --- | --- | --- |
| Tabs、分组与跨 Tab 拖放 | 命名材料集，例如“本次发布”“报销资料”；同一材料集提供时间线与分区视图 | P1 |
| 多选与批处理 | 多选添加、移动、复制、导出、合并文本、按序取用 | P0/P1 |
| 条目备注与标签 | 材料标题、说明、来源与标签；便笺是独立可编辑内容 | P1 |
| 本地目录同步 | 便笺保存成普通 `.md`，支持外部编辑后刷新与冲突处理 | P0 保存，P1 双向更新 |
| Pin 的防清理语义 | 明确区分“保留条目”“列表置顶”“固定到桌面” | P0 |
| Commands / scripting | 先做有限的批量操作：拼接、去重、格式清理、导出、总结；插件/脚本后续再议 | P1/P2 |
| 不活跃内容卸载 | 面板关闭时释放正文、预览、页面缓存与订阅 | P0 |

CopyQ 的 Pin 是固定行和防误删机制，不能当作已有桌面浮窗功能。借鉴其操作与存储语义，不照搬复杂偏好设置和脚本系统。当前项目已有标签、置顶、清理与快捷键，不应为“对标 CopyQ”重复实现。

## 4. 功能范围与默认交互

### P0：可靠收集与再次取用

- 独立 Shelf 窗口，沿用当前 Fluent 控件、间距、主题和滚动条；默认右侧停靠，可切换左侧或浮动。
- 快捷键/托盘/主窗口按钮呼出；正常点击空白处不按剪贴板弹窗规则立刻隐藏。
- 默认时间线按“加入暂存区的时间”倒序分组，保留原始复制时间和来源。后续拖动排序使用独立位置字段，不篡改时间戳。
- 从资源管理器拖入任意文件；从浏览器/编辑器拖入文本、URL；从历史添加一条或多条；支持面板粘贴与文件选择器兜底。
- 内部拖动重排；向其他程序拖出文件与文本。拖出文件默认复制语义，避免误移动原文件。
- 双击取用/打开、复制、定位文件、重命名材料标题、搜索、删除、撤销最近移除。
- 文本摘要、图片缩略图、文件类型/大小/缺失状态；大图按需预览。未知格式显示图标并交给默认应用打开。
- 重启恢复，且清空剪贴板历史不影响已收集材料。暂存区不受历史条数上限与“粘贴后删除”设置影响。
- 删除条目默认只移除收集关系；外部源文件永不随之删除，托管附件在无人引用后回收。
- 首版不递归展开目录、不后台抓取网页、不自动解析所有文件。目录作为引用保存。

### P0：Markdown 便笺

- 新建空白便笺；将选中文本另存为便笺；支持基础 Markdown 编辑、预览、复选框、链接和本地图片。
- 用户选择保存目录，创建 `2026-10-16_143025_123.md` 形式的文件；内部使用 UUID，同毫秒冲突时追加短 ID。标题取首个标题行，不因改标题频繁重命名文件。
- 文件保存 UTF-8；数据库仅索引路径、标题、摘要、更新时间与版本。正文以 `.md` 为准，不同时维护两套正文真相。
- 输入后约 500–1000 ms 防抖保存；同目录临时文件加安全替换，失败时保留原文件和未保存状态，失焦时尝试保存。针对只读目录、磁盘满、路径失效给出可恢复状态。
- 编辑器基础版先用轻量输入组件；只在打开编辑器时加载 Markdown 解析与预览，禁用原始 HTML/脚本和默认远程图片。
- 支持在默认编辑器打开；首版可手动刷新，P1 增加目录变更通知、冲突副本与删除/移动后的重新关联。
- 普通 `.md` 是明文。敏感条目转便笺时明确呈现明文落盘后果；敏感便笺加密属于后续独立能力。

### P1：分区与桌面固定

- 命名材料集，集内可选分区；时间线与分区是同一批数据的不同视图，避免复制内容。
- 多选移动、合并、批量复制/导出、选择性按序粘贴、归档材料集。
- 将文本、便笺、图片、文件卡片固定成可移动、可缩放的桌面浮卡；修改便笺时与 Shelf 显示同一内容版本。
- 首版将“固定到桌面”定义为普通独立浮窗，可选始终置顶；记录显示器、位置和 DPI，断开显示器后移回可见区域。
- “嵌入壁纸层且遵循 Win+D / 虚拟桌面行为”需另行验证 Shell 集成，不承诺普通 always-on-top 自动满足它。
- 默认建议最多同时打开 3 张浮卡；更多条目仍可收藏并折叠为一个浮动卡片组。若用户需要大量独立浮卡，再测量并评估原生轻量窗口。

### P2：显式材料集 AI

- 多选材料后选择总结、提取待办、对照、翻译或自定义提问；支持本地服务与云端 provider。
- 发送前查看材料清单、提供方、抽取内容和大小/token 预算；“本地”明确表示本地服务地址，不代表应用内已集成推理引擎。
- 后端只根据本次选中的 ID 与版本构建上下文；允许发送的内容在请求发出前固定，不因文件后来变化而静默改变。
- 保留来源编号，结果新建便笺或结果卡片，附输入版本与来源；不覆盖材料。
- 复用模型配置与请求客户端，新增 `run_staging_action(item_ids, expected_revisions, action, provider_id)`，不借道会回写历史的 `call_ai`。
- 先支持文本与 Markdown；图片视觉模型、PDF/Office 抽取、OCR 按需逐步添加，明确不支持格式，不承诺“任意文件都能给 AI 理解”。
- 对长材料先显示限额与分批策略，避免沿用当前 10000 字符静默截断。请求可取消、超时、重试；完成后清理临时抽取缓存。
- 材料内容是待处理数据，不能赋予工具执行权限；不自动读取相邻文件、不自动发送全历史、不默认生成向量库或加载本地模型。

## 5. 数据与实现方案

建议新增 `src/features/staging/`、`src/features/notes/`、`staging_cmd.rs`、`staging_repo.rs`、`staging_service.rs`、`note_service.rs`、`context_builder.rs`。这是拟议结构，不是已存在文件。

最小数据实体：

| 实体 | 关键内容 |
| --- | --- |
| `collections` / `sections` | 名称、顺序、创建时间、归档状态 |
| `staging_items` | UUID、集合/分区、类型、标题、摘要、加入时间、原始来源时间、来源历史 ID（仅溯源）、内容引用、revision |
| `assets` / `asset_refs` | 托管附件路径、可靠内容哈希、MIME、大小、引用关系；不在列表响应中发送二进制 |
| `desktop_cards` | item_id、窗口位置/尺寸、显示器、置顶与折叠状态 |
| `note_index` | `.md` 路径、摘要、内容版本/哈希、更新时间，不复制完整正文 |

导入采用明确的保存模式：

- **剪贴板文字/图片**：保存加入时的快照；临时会话条目也需转为持久内容。首版建议复制历史托管附件到暂存区专用目录，先保障与现有删除逻辑隔离；之后迁移到共享资产引用与回收。
- **外部文件**：默认保存路径引用，界面标明“引用文件，原文件变化会影响内容”；提供“保存副本”操作。修改前后版本需可辨认，文件不存在时显示失效并可重新定位。
- **虚拟文件/临时文件**：读取后转为暂存区托管副本，不能把外部临时路径当作长期存储。
- **目录**：首版仅引用目录；需要打包/扫描时由用户发起并设置体积和数量上限。
- **便笺附件**：相对路径放在指定目录下的附件子目录；复制/导出便笺时携带依赖，删除便笺不擅自删除用户目录中的其他文件。

导入事务使用“写临时附件 → 确保落盘 → 数据库提交 → 发布事件”，失败清理临时内容；启动时回收超期、未被提交的临时文件。最终共享资产实现需覆盖显式删除、历史限额、自动清理和云同步触发的删除路径。

列表使用摘要 DTO 与游标分页，索引覆盖 `(collection_id, added_at, id)` 和分区排序；正文通过 ID 按需取。前端只缓存附近页面，例如 3 页 × 50 条；数据库保持完整索引。查全量内容与生成缩略图不能长期占住剪贴板共用的 SQLite mutex。

窗口用独立入口和按需模块加载，避免每个浮卡挂载 `App`、监听完整历史或加载主题商店。事件仅携带 ID / revision，按窗口定向通知；后台服务维护真实状态。

### Windows 拖放是首个技术验证点

- 当前主窗口 `dragDropEnabled: false`，同时注册自定义 OLE 目标。不能简单切成 true，必须明确由谁接收外部拖放。
- 扩展为按窗口注册的 OLE 接收器，增加 `CF_UNICODETEXT` / HTML 等文本格式，保留 CF_HDROP、虚拟文件支持；内部拖放使用 ID 协议，不复制正文。
- 全局 `emit` 改为目标窗口消息，保留坐标以支持分区命中。URL 默认收集为链接，不因拖入而自动下载。
- 向外拖出需独立实现/验证原生 OLE drag source、IDataObject 与 CF_HDROP/文本/HTML；内部卡片重排成功不代表跨应用拖出可用。
- 实测资源管理器、浏览器选中文本与图片、编辑器、多文件、不同权限进程、中文与长路径、多屏 DPI；不兼容来源提供粘贴/文件选择兜底。

## 6. 性能与内存评估

### 6.1 先确立测量口径

统计 Rust 主进程及其所属 WebView2 browser/renderer/GPU/utility 进程；不把机器上所有 `msedgewebview2.exe` 算进来。WebView2 可能共享进程，因此不能假设“一张浮卡恰好一个 renderer”。

同时记录：进程树 Private Bytes（私有提交）、Private Working Set（私有驻留）、Working Set（含共享页，仅辅助）、JS heap、GPU 内存、进程数。多个 Working Set 直接求和可能重复计算共享页，不等价于物理总内存。

### 6.2 量级推导与风险

- 1,000 条摘要若按每条 1–2 KiB 估算，纯载荷约 1–2 MiB，JS 对象、索引、重复字符串与框架另计。应靠有界页缓存避免线性积累；数据库中有 10,000 条不应意味着全量驻留。
- 320×180 RGBA 缩略图约 0.22 MiB，30 张约 6.6 MiB；512×512 则约 1 MiB/张。CSS 缩小原图不能替代生成实际小尺寸缩略图。
- 一张 3840×2160 RGBA 图约 31.6 MiB。解码原图、编码缓冲、画布和 GPU 纹理并存时可能是数倍，压缩文件只有几 MiB 也不代表解码后同样小。
- Base64 文本长度约为二进制的 4/3，再叠加 IPC、JSON 和引擎字符串表示。不要断言 JS 字符串一定占两个字节，也不要以文件压缩大小估算进程峰值。
- 文件路径引用不会把文件本体常驻内存；复制文件应流式进行。网络盘和海量小文件的主要风险可能是延迟、I/O 和元数据数量。
- Markdown 便笺文本通常很小，编辑器依赖、语法高亮、历史撤销和嵌入图才可能成为主要开销。大便笺可退化成普通文本编辑，避免全量实时预览。
- 新 WebView / 浮卡可能增加数十 MiB，复杂内容可能超过 100 MiB；是否共享 renderer、WebView2 版本、DPI、透明材质与驱动都会影响结果，必须在本机 release 包测量。
- 本地 AI 若作为独立服务运行，其模型 RAM / VRAM 另算；不应混在 Shelf UI 内存里，也不能从面板轻量推导本地模型轻量。

### 6.3 候选预算：相对同场景旧版本的新增开销

以下是开发目标与粗估区间，不是当前产品实测数据。以进程树 Private Bytes 增量作为主比较项，同时观察私有驻留与 GPU。

| 场景 | 候选预算/初步量级 | 关键策略 |
| --- | --- | --- |
| 功能关闭或从未打开 | 目标 ≤5 MiB | 不预建 Shelf/浮卡，不启动笔记扫描与 AI |
| Shelf 打开，100 条文本/文件引用 | 先预留约 30–100 MiB，超过需分析 | 一个轻量 WebView、摘要分页、按需编辑器 |
| 1,000 条混合材料，视口附近约 30 张小缩略图 | 在空 Shelf 上再预留约 10–30 MiB，含缓存/对象余量 | 缩略图真实降采样，缓存按字节限额 |
| 新增一张轻量独立桌面浮卡 | 粗估 15–60 MiB，复杂预览可更高 | 用实际 0/1/3/10 张曲线决定默认上限 |
| 大图原图预览 | 每张额外数十至上百 MiB 峰值均有可能 | 一次只打开一张大图，解码并发 1 |
| Shelf 关闭且无浮卡，空闲回收后 | 目标回到相同窗口预热基线 +10 MiB 以内 | 释放内容和缓存，必要时销毁 WebView |

区间不能机械相加：进程共享可能摊薄成本，缓存和 GPU 也可能放大成本。若额外独立 WebView 无法达到预算，应比较“主窗口复用为 Shelf”与“原生卡片”方案，不以牺牲可靠保存来省内存。

初始缓存策略：可见及近邻缩略图约 16 MiB/活动视图，应用侧统一预算约 32 MiB；这是受控缓存的目标，不保证浏览器内部解码/GPU 总额同样被硬限制。后端解码任务并发 1–2，原图预览 1；超大像素图先检查尺寸与分配限额。隐藏时停止动画、媒体、轮询，移除预览节点并释放 object URL；关闭窗口并不保证运行时立即将所有页返还给 OS。

### 6.4 CPU、I/O、延迟与磁盘

- 贴边呼出复用已有逻辑，优先事件驱动；需要轮询时降低空闲频率，避免每个浮卡独立轮询鼠标。
- 摘要搜索先用元数据索引；全文检索在实际需求下按集合构建，避免启动时抽取所有文档或生成 embeddings。
- 便笺自动保存防抖，只监听用户选定目录，批量合并变更；不递归全盘扫描。
- 文件复制、哈希、缩略图生成进入有界后台队列，可取消、有进度；哈希只针对托管/去重需要，不因拖入引用就读取数 GiB 文件。
- 首版隔离附件副本会增加磁盘用量；后续按可靠哈希共享。缩略图设置磁盘配额与可重建清理策略，独立显示暂存区存储占用。
- 初始验收目标：暖启动呼出 p95 <150 ms；冷创建 p95 <800 ms；本地摘要搜索 p95 <100 ms；拖入后占位反馈 <100 ms，实际复制/预览异步完成。以上是目标，需按硬件与数据集校准。

## 7. 性能与可靠性验收矩阵

对旧版和新增版本使用相同 release 配置、WebView2 版本、显示分辨率/DPI、数据集与同步设置；分别测冷启动和预热后的状态，每场景至少 5 次。调试构建和开着 DevTools 的数字不能当 release 结论。

1. 托盘空闲、主窗口预热、Shelf 关闭、Shelf 首次打开与重复打开。
2. 100/1,000/10,000 条文本及混合条目；反复滚动、切集合、搜索，确认页缓存有界。
3. 100 张 4K 图片，观察导入峰值、滚动稳态、单图预览与关闭后回收；混入超大尺寸与损坏图片。
4. 1 GiB 文件引用与流式复制；大量小文件、失效路径、网络盘断开、磁盘满；确认无全文件内存载入。
5. 0/1/3/10 个浮卡，多屏 100%/150%/200% DPI、休眠恢复、显示器拔插。
6. 便笺连续输入、外部编辑、同时编辑、编辑时删除文件、只读目录、保存中断；确保不会覆盖更新版本或丢失原稿。
7. 开关 Shelf 100 次、预览数百次、重复拖放，记录 Private Bytes、句柄/GDI 对象、事件订阅与 WebView 数量，排查持续增长。
8. 清空/限额淘汰历史、删除同源历史项、关闭持久历史、重启；已入 Shelf 的快照仍存在。删除 Shelf 引用不能伤及源文件。
9. AI 选中集合与实际请求一一对应；默认未选中任何项；云端请求材料清单可核对；取消/失败不修改原材料；响应不成为执行指令。
10. 空闲 30 分钟与持续使用 2 小时；记录最终 60 秒的中位数、p95、整段峰值与关闭后 60 秒/5 分钟的回收值，避免用单次截图判断。

可使用 Windows 性能计数器 / GetProcessMemoryInfo 记录进程指标，DevTools 仅用于单独诊断 JS heap 与节点泄漏；GPU 与共享进程使用对应工具补充。不要通过周期性 EmptyWorkingSet 制造“内存下降”的假象。

## 8. 开放式实施顺序与决策门槛

| 阶段 | 交付 | 完成门槛 | 粗略工作量 |
| --- | --- | --- | --- |
| A：可行性与基线 | 空 Shelf、多源拖入/拖出样机、进程树基线、1/3/10 浮卡实验 | 原生拖放可用，窗口成本可接受 | 2–4 人日 |
| B：核心收集 | 独立数据模型、文件引用/快照、时间线、分页、删除与恢复 | 历史清理/重启不丢材料，导入不阻塞粘贴 | 5–8 人日 |
| C：便笺 | 时间戳 `.md`、编辑/预览、可靠保存与外部打开 | 保存失败可恢复，文件与索引可重建 | 3–5 人日 |
| D：分区与浮卡 | 材料集、手动排序、桌面浮卡、多屏适配 | 3 张浮卡预算通过，状态与正文一致 | 4–7 人日 |
| E：AI 与扩展 | 显式上下文、文本批处理、结果另存、可取消请求 | 请求边界和版本可核对、原材料不变 | 3–6 人日 |
| F：加固 | 长时压力、拖放兼容、数据迁移/备份、安装包回归 | 性能/可靠性矩阵通过 | 3–5 人日 |

合计约 20–35 人日，仅作为熟悉代码后的范围估算；PDF/OCR/视觉模型、真正壁纸层嵌入、跨设备合并和通用插件系统另估。阶段可调整，A 阶段实测后再承诺窗口结构与内存目标。

最小可用版范围建议为 B+C，加上 A 的必要验证；D 和 E 独立交付。AI 不阻塞基础 Shelf 发布。每阶段保留功能开关、旧数据可读与迁移备份，避免一开始重写整套剪贴板存储。

## 9. 待验证而非阻塞当前设计的选择

- 时间线先行；若用户主要按项目工作，再把材料集设为默认入口。
- 默认外部文件引用，显式“保存副本”；如用户主要收集临时文件，可增加集合级默认快照。
- “固定到桌面”先使用独立浮窗；真正壁纸层实现依据 Win+D 与虚拟桌面预期另立实验。
- 便笺默认普通 Markdown 文件；加密与通用外部编辑互通的取舍需独立定义。
- 新数据默认本地，不自动纳入历史的云同步/MQTT。同步需要独立选择、附件策略、冲突与删除语义。
