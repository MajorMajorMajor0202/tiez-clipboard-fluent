# 条目拖出

## 图片、文件与路径文本

旧实现把图片、文件和视频的 `content` 写入 `text/plain`，再添加 `text/uri-list`。接收方可以选择纯文本格式，所以会得到本地路径，而不是可上传的图片或文件。仅拼接 `file:///` 不会创建原生文件拖拽对象。

Windows 下，主列表和桌面贴图改用 Shell 的 `IDataObject` 与 OLE `DoDragDrop`，提供真实文件格式（`CF_HDROP`），仅允许复制。已有文件不读入 WebView，也不通过剪贴板中转。普通文本条目即使内容像路径，也继续作为文本处理。

内嵌 Base64 图片先保存为保留原格式的临时文件，再交给 Shell；文件在拖动结束后仍保留，供延迟读取的接收方使用。文件名前缀为 `TieZ_Clip_`，沿用程序启动时的临时文件清理。多文件按换行拆分，`file:` URI 按 URL 规则解码；Unicode、空格、`#`、`%` 不作为额外分隔符。

其他平台保留 HTML 拖动回退，文件只提供 URI，不附加路径纯文本；Windows 原生拖出不依赖额外的第三方库。

## 内部标签页拖动

原生拖动期间记录源条目 ID，接收文件的事件携带 `itemIds`。拖到标签页时分配原有条目，不重新导入路径或临时图片。去重记录跨渲染保留，兼容原生接收端同时发出的两种拖放事件。

文本拖入工作区也优先使用拖动中的条目 ID（包括多选），而不是重新调用 `add_manual_item`。DOM 已完成归类后，记录内容及目标工作区，拦截随后重复上报的原生文本事件，避免清空拖动标记后误建 Manual 副本；已知不同条目 ID 即使内容相同也仍分别归类。只对真正外部的文本保留导入行为，内部条目落在非工作区位置不会退回导入。

回归：`npx vitest run src/shared/lib/tabTextDrop.test.ts`，覆盖原生双事件、DOM 与原生重复上报、多选、无目标、同文本不同 ID 及外部文本。

OLE `GetData` 得到的 `STGMEDIUM` 使用 `ReleaseStgMedium` 释放，以遵守数据对象自己的资源所有权；不再调用针对 `WM_DROPFILES` 句柄的 `DragFinish`。
接收端检测格式时只接受 `QueryGetData` 的 `S_OK`，不再把 `S_FALSE` 误判为有数据。跨文件夹多文件直接使用 Unicode `CF_HDROP` 列表，避免平面 Shell 项目数组的同文件夹限制。

## 快捷键提示

采用参考截图的灰底白字方牌，常规条目距右侧和底部均 8px，紧凑条目分别为 6px、4px。提示绝对定位，不改变条目或正文尺寸，保留系统强制颜色模式支持。

Fluent UI Contrib 提供 `@fluentui-contrib/react-keytips`，但这里仅修改现有提示的外观，不引入另一套键盘事件管理或浮层定位。

## 验证

浏览器回归检查提示的颜色、直角、右下角位置、普通/紧凑尺寸不变，以及文件 URI 与普通路径文本的区分。
Windows 回归检查真实 Shell 数据对象提供 `CF_HDROP`，覆盖不同文件夹、多文件、Unicode 路径、内嵌图片、原始 Base64 图片、编码 URI 和无效来源。
目标应用是否接受附件取决于其拖放支持；普通文本输入框不会因此变成图片编辑器。
