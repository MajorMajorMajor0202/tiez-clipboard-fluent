# 列表快捷粘贴

主窗口显示时，按住所选修饰键（默认 Alt）查看前十项的数字提示，按 1–9、0 粘贴对应条目。
编号跟随当前工作区、搜索和类型筛选，置顶项优先。数字小键盘同样可用。
编辑内容、便笺、对话框和其他面板不响应列表快捷粘贴。

列表快速粘贴与原有的全局置顶粘贴都位于「剪贴板与热键」页。列表修饰键支持 Alt、Ctrl、Shift 及它们的组合，也可以关闭。
相同组合冲突时，主列表显示期间优先粘贴当前列表；隐藏后仍按原规则执行全局置顶粘贴或复制后工作区归类。

## 实现

- `useListQuickPaste` 读取已加载列表的前十项，复用普通粘贴流程及删除、排序设置。
- 主窗口取得焦点时使用 DOM 键盘事件；不激活弹出窗口时，由现有 Windows 钩子定向转发到主窗口。同一次按键只由一条路径处理。
- KeyTip 使用绝对定位，不参与尺寸计算；紧凑模式中垂直居中。松开修饰键、隐藏窗口或失去焦点时清除提示。
- 防止长按重复和并发粘贴；精确匹配修饰键，排除额外修饰键、Win 和 AltGraph。
- 不新增数据库查询、计时轮询或内容副本。提示最多十个，移除了原先刷新编号时额外读取 256 条历史的请求。

## 设置位置

- 常规：启动与窗口、面板入口、声音与打开方式、重置。
- 剪贴板与热键：列表快捷键、全局快捷键、复制后归类、数据位置、采集存储、粘贴行为。
- 外观：主题与语言、列表显示、字号、背景、便笺外观。
- 隐私、同步、AI、数据清洗等栏目维持原来的位置和顺序。

已有设置值保持不变。新增 `app.list_quick_paste_modifier`，默认 `alt`；保存、启动加载和重置均同步到 Windows 钩子。

## 验证

浏览器回归覆盖普通/紧凑条目与正文位置、尺寸不变，按下/松开 Alt、前十项及 0、长按防重复、工作区与搜索顺序、编辑和对话框避让、组合键避让、失焦及禁用状态。
Windows 钩子通过原生编译检查；真实桌面中的焦点恢复及向外部应用粘贴仍需手动验证。

## 窗口切换后的恢复

- 只把可见的对话框、菜单和选择列表当作拦截条件，忽略隐藏或保留的弹层 DOM。
- 输入框的避让按当前焦点判断，避免已筛出列表的旧编辑条目 ID 永久禁用快捷键。
- 每次新的修饰键按下重新开始一轮快捷操作，漏掉前一次 keyup 后也可恢复。
- 显示、隐藏事件会同步原生导航状态，覆盖托盘恢复等没有经过 toggle_window 的入口。
- 初始可见性查询有版本保护，较旧的异步结果不能覆盖后续显示或隐藏事件；卸载后的查询也不能再写入状态。

浏览器回归模拟了这些恢复场景及原生事件转发。浏览器测试的 Vite 缓存独立保存，避免与正在运行的开发服务共用依赖优化缓存。

Alt+C 唤起及搜索框焦点交接还需要区分事件的新旧：

- 已有 DOM 修饰键按下时，忽略原生交出处理权所产生的迟到 `hide`。
- 聚焦已显示窗口也会产生 `window-shown`；它不能清除当前仍按住的修饰键提示。
- 窗口激活辅助代码注入的 VK_FF 会变成 `Unidentified` DOM 按键，不能把它当成用户取消快捷提示。

这些顺序均加入模拟原生事件的浏览器回归。

## 首次启动正常、再次唤起失效

首次启动会激活主窗口，后续唤起通过不激活显示保留原输入窗口，二者分别依赖 DOM 和原生钩子。
原生钩子现在比较 `GetForegroundWindow` 与初始化时保存的主窗口 HWND，并用 `IsWindowVisible` 确认窗口确实显示；不再用可能滞后的 `IS_MAIN_WINDOW_FOCUSED` 缓存决定按键归属。

后台原生转发事件已确认主窗口显示且键盘属于其他窗口，因此前端不再用残留的 `document.hidden`、`document.hasFocus()` 或 `activeElement` 将它拒绝。前台原生提示和 DOM 输入路径继续避让真正聚焦的编辑器，对话框和非列表页面也继续禁用快捷粘贴。

本次只调整快捷键路由，保留不激活显示、粘贴目标记录、剪贴板写入和粘贴后的焦点恢复逻辑。Rust 改动需要重新编译并重启进程才能生效。

原生修饰键事件使用 `show` 表示未激活窗口、`show-focused` 表示前台窗口，`released` 表示实体按键释放或组合取消。有焦点的页面继续处理 DOM 按键：实测首次启动可能只有 DOM 收到修饰键事件，不能依赖原生钩子单独显示提示。
实测还发现实体 Alt 松开后会紧接一个带 `LLKHF_INJECTED` 标记的 Alt 按下；系统异步状态随后已回到松开。提示事件过滤注入的修饰键，避免合成按下重新点亮编号。此过滤只作用于列表提示通知，不拦截系统事件，也不更改粘贴过程需要的模拟输入。
数字键粘贴仍按前台 DOM、后台原生转发区分，保持编辑器避让与原输入窗口的回贴行为。

数字键与提示统一使用钩子记录的实体修饰键状态，按左右键分别计数；模拟释放或按下不会改变这份状态。每次新的实体修饰键按下也清除旧数字键的防重复锁，避免遗漏 keyup 后阻挡下一轮操作。

窗口显示后，页面调用 `get_list_quick_paste_state` 读取当前状态：Alt+C 唤起后只松开 C，保持 Alt 即可看到编号并接着按数字。查询结果有版本保护，松开或隐藏发生后，迟到的查询结果不能重新点亮编号。
